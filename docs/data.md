# 记录口径

登记请求、应用调用和用户日活三个粒度的事实，按单个事实表生成基础统计，并在版本化指标定义上执行明细与汇总查询。

requests 的主键为 request_id；calls 的主键为 call_id，request_id 是外键；user_days 以 user_id 与 day 联合唯一。各表以 revision 表示全表版本。queries 是业务查询意图，catalog 中的基础字段已有明确单位和粒度。

数据字段采用稳定的英文标识符。编号是业务身份，不由输入数组中的位置决定。未到达的结果与已经观察到的否定结果是不同事实。货币、时间和统计单位应按字段约定解释，不在读取时默默变换。

## 两套成功率不能混算

* 请求成功以 requests.success 为准，描述一次智能体订票请求的最终结果，粒度是 request；
* 应用成功以 calls.success 为准，描述单次应用调用结果，粒度是 call；
* 一个请求可关联多条调用。calls 到 requests 是有外键背书的多对一；反方向是一对多扇出，只有指标定义显式声明 bridge（multicast 或 pick）才允许通行。
* 比例指标的分子与分母必须同实体粒度、同时间锚点，且分母的有效人群包含分子。过滤不兼容、粒度不一致或未声明连接都在编译期拒绝。

## 汇总不是数字相加

跨天与跨分组汇总合并的是可合并中间状态：

* scalar 计数可加；
* 去重指标保留实体集合，按并集合并——月活是跨日用户集合的大小，不是每天去重用户数之和；
* 分位数保留全部样本，在合并后的样本上按最近秩重算；
* 比例分别合并分子状态与分母状态，不把已经算出的比率再相加；
* 状态族不兼容、缺少分区或缺少中间状态时拒绝汇总，输出 null 而不是零。

## 版本与缓存

指标定义按 name 与 version 不可变保存；事实分区按内容摘要寻址，calls 精确到 (day, app)。缓存键同时绑定指标版本、表达式摘要、查询形状与分区摘要：修订一条调用只失效对应分区相关的缓存条目，无关结果不重算。历史分区快照不可变，replay 凭历史运行记录复现修订前结果。

当前命令的输出只解释当前公开计算，不承诺示例覆盖全部业务情形。批量重放应使用新的输出位置，避免人工查看上一次运行留下的文件。
